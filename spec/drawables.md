# 5. Drawables, media and charts

Objects drawn on a page or slide: images, text boxes and shapes, groups, sounds and movies, and charts, with where they are placed and how their geometry is stored. Tables are drawables too, described in [4. Tables](tables.md). Every finding links to the experiments that support it, with a confidence level as defined in [CONTRIBUTING.md](../CONTRIBUTING.md#confidence). Records, object IDs and types are as described in [1. Container](container.md).

## On the page or in the text

An object is either in the text (a U+FFFC with an attachment, and its drawable's field 1.2 names that text) or on the page (listed by type 10015, with no field 1.2; that list, in its field 1, is what Pages draws on the page, and must include the body's text, *confirmed* by writing it, [0424](../experiments/0424-writing-the-page-objects-list.md); its order is the stacking order, back to front, and the body's text wraps only around objects listed after it, *confirmed*, [0425](../experiments/0425-writing-stacking-order.md)). *Likely* ([0020](../experiments/0020-a-table.md), [0052](../experiments/0052-floating-table.md))

The document root (object 1, type 10000) names the two page-level records: field 3 the type-10010 record and field 20 the type-10015 record, *confirmed* ([0023](../experiments/0023-an-image.md), [0482](../experiments/0482-objects-on-later-pages.md)). There is one type-10015 list for the whole document, whatever page its objects are on; the body's text is in it once, first in a document made by placing objects ([0482](../experiments/0482-objects-on-later-pages.md)).

### Which page an object is on

Type 10010 says which page each object placed on the page ("Stay on Page") is on. Its repeated field 1 has one entry per page that has such objects: 1.1 is the page number, counting from 0 at the document's first page, and each repeated 1.4 names one object on that page in 4.1.1. Pages without placed objects have no entry, and Pages writes the entries in page order. *Confirmed* by writing the page number, which moves the object to that page ([0482](../experiments/0482-objects-on-later-pages.md), [0484](../experiments/0484-writing-an-object-s-page.md)).

```
10010 field 1: { 1: 1, 4: { 1: { 1: 1732688 } } }                                  page 2: one object
               { 1: 2, 4: { 1: { 1: 1732695 } }, 4: { 1: { 1: 1732724 } } }         page 3: two objects
```

- The number counts every page of the document. It doesn't restart in a new section, and a different first page or different left and right pages don't change it, *confirmed* ([0486](../experiments/0486-page-numbers-across-sections.md)).
- Entries out of page order are read correctly; Pages sorts them when it saves ([0484](../experiments/0484-writing-an-object-s-page.md)).
- The order of the objects within an entry changes nothing drawn: type 10015 alone decides which is in front. Pages writes them in their 10015 order, *likely* ([0485](../experiments/0485-order-of-objects-on-one-page.md)).
- An object must be in both records to be drawn. One in 10015 but in no 10010 entry isn't drawn, and AppleScript doesn't count it, *confirmed* by writing ([0484](../experiments/0484-writing-an-object-s-page.md)).
- A page number past the document's last page adds no page: Pages keeps the object and the number but doesn't draw the object, *confirmed* by writing two such numbers ([0484](../experiments/0484-writing-an-object-s-page.md)).

The object's position (geometry 1.1.1) is from the top-left corner of its own page, not of the document, *confirmed*: written to another page number, an object is drawn at the same spot on that page ([0482](../experiments/0482-objects-on-later-pages.md), [0484](../experiments/0484-writing-an-object-s-page.md)). When text before it grows or shrinks, a placed object keeps its page number and its position on that page; the text flows on past it, and Pages keeps the pages that hold such objects even when the text no longer reaches them, *likely* ([0483](../experiments/0483-text-before-objects-on-the-page.md)).

### Move with Text

An object set to Move with Text is anchored in the text as other attachments are: a U+FFFC, an entry in the text's attachment runs (field 9) at that position, a type-2003 record whose field 1 names the object, and the text as the object's parent in drawable field 1.2, *confirmed* for a picture as for a table ([0020](../experiments/0020-a-table.md), [0487](../experiments/0487-move-with-text.md)). It still floats: it stays in type 10015, keeps its own geometry and wrap, and has no entry in type 10010, since its page follows the text. The 2003 record holds its offset in points: field 3 from the left edge of the text column, field 5 from the bottom of the line holding the U+FFFC. Pages draws the object from the anchor and this offset, and doesn't update 1.1.1 in the file when the text before it moves, so a reader should do the same. *Likely* ([0487](../experiments/0487-move-with-text.md)). Fields 2 and 4 of the 2003 record (0) are *unknown*.

Inline with Text is the same attachment with wrap type 1.3.1 = 0: the object is drawn in its line like a character, after the text before the U+FFFC, with its bottom on the line's baseline, and the line grows to hold it; its 1.1.1 and the 2003 offset aren't used. With any other wrap the attached object floats at the offset. Pages leaves an inline object out of type 10015, but an attached object is drawn the same whether it is listed there or not, so a reader should go by the wrap type. *Confirmed* by writing ([0489](../experiments/0489-the-text-wrap-menu.md), [0490](../experiments/0490-writing-inline-with-text.md)); the baseline is *likely*.

### Text wrap

Drawable field 1.3 holds the object's text wrap, as the Arrange sidebar sets it ([0488](../experiments/0488-writing-text-wrap.md), [0489](../experiments/0489-the-text-wrap-menu.md)):

| Field | Holds |
| --- | --- |
| 1.3.1 | How text wraps. The sidebar's entries: 4 Automatic, Pages' default, which wrapped on both sides in the case seen; 1 Around, on the sides 1.3.2 chooses; 2 Above and Below, with nothing beside the object; 5 None, the object drawn over the text; and, for an object attached to the text, 0 Inline with Text (see [Move with Text](#move-with-text)). *Confirmed* by the sidebar and by drawing written values. Values the sidebar doesn't offer: 0 on an object on the page is drawn as None, and 3 wraps on one side only, the wider one in the case seen. *Likely* |
| 1.3.2 | The sides for wrap 1: 0 left, 1 right, 2 both. The sidebar has no choice of sides and always writes 2; wraps 3 and 4 ignore it. *Likely*, by writing |
| 1.3.3 | Text fit: 0 the box, 1 the outline (Pages' default), which lets lines that only partly reach the object's top or bottom come closer. *Confirmed* |
| 1.3.4 | The spacing between the text and the object, in points, beside, above and below it; 12 by default. *Confirmed* by writing it |
| 1.3.5 | The alpha for outline fit, as a fraction: 0.5 by default, the sidebar's 50 %. *Likely*; how it changes the wrap isn't tested |
| 1.3.6 | 0; 1 changes nothing drawn. *Unknown* |

## Geometry

In the geometry of any drawable (field 1.1), 1.1.1 is the position and 1.1.2 the size of the unrotated box, in points, and 1.1.4 its rotation in degrees about its centre, counter-clockwise on the page (*confirmed*, [0056](../experiments/0056-image-rotation.md), [0097](../experiments/0097-keynote-shape-rotation.md)). Field 1.1.3 holds flags, normally 3; bit 0x4 is a horizontal flip ([0213](../experiments/0213-flipped-shape.md)). A vertical flip is stored as a horizontal flip plus a rotation of 180° ([0214](../experiments/0214-vertically-flipped-shape.md)); both *confirmed* by writing them and drawing the result ([0373](../experiments/0373-writing-a-flip.md)). Fields 1.10 and 1.11 name the object's title and caption: type-633 text shapes, with field 3 = 2 for a title and 1 for a caption, or type-3097 placeholders when hidden, *confirmed* ([0228](../experiments/0228-caption.md), [0229](../experiments/0229-title.md)). Each shape's text record holds the words shown; when it is empty Pages draws a prompt in its own language instead (*confirmed* by writing them, [0374](../experiments/0374-writing-a-caption-and-title.md)). Numbers tables get captions the same way ([0231](../experiments/0231-table-caption.md)). Field 1.5 is 1 for a locked object ([0100](../experiments/0100-locked-object.md); position, size, rotation and lock *confirmed* by writing them, [0303](../experiments/0303-writing-geometry.md), where AppleScript's `position` turned out to be the corner of the rotated object's bounding box) and field 1.8 is its accessibility description, in Keynote and Pages alike (*confirmed*, [0102](../experiments/0102-image-description.md), [0177](../experiments/0177-pages-image-description.md)). A line is a box of zero height, rotated. *Likely* ([0051](../experiments/0051-line.md)). It runs from the box's left end to its right end, turned about the box's centre by the rotation, counter-clockwise on the page, *confirmed* by writing the rotation; its length comes from its path, not its width ([0403](../experiments/0403-writing-a-line.md)): it is the path's natural width (1.3.5.2.1), with the path's points stretched to fill it, laid out from the box's left end, *confirmed* by writing it ([0404](../experiments/0404-writing-a-line-length.md)).

## Images

An image placed on the page, rather than in the text, is a record of type 3005 in `Document.iwa`, listed next to the body text by page-level records (types 10015 and 10010; see [Which page an object is on](#which-page-an-object-is-on)). It holds its position and size in points in field 1.1, like a table's drawable, and the data ID of its file in field 11.1, with a reduced copy for a large image in field 12 ([0148](../experiments/0148-large-image.md)) (see [container.md](container.md#data-files)). *Likely* ([0023](../experiments/0023-an-image.md)). Field 9 is its natural size and fields 1.1.2 and 4 the size it is drawn at ([0055](../experiments/0055-image-size.md)); 1.1.2 alone decides the drawing, *confirmed* by writing it and measuring, and field 4 is a copy ([0348](../experiments/0348-writing-an-image-size.md)). Field 9 written alone changes nothing drawn either ([0447](../experiments/0447-writing-an-image-s-sizes.md)). Field 3 names its image style (type 3016), whose field 11.2 is the opacity from 0 to 1 ([0057](../experiments/0057-image-opacity.md)) and 11.4 the reflection, with its strength in 11.4.1 ([0099](../experiments/0099-image-reflection.md); both *confirmed* by writing them, [0304](../experiments/0304-writing-opacity-and-reflection.md)). Image field 7 is 1 for a media placeholder, an image the user is meant to replace ([0244](../experiments/0244-media-placeholder.md)). Image field 14 holds adjustments as fractions (exposure in 14.1, saturation in 14.2), and field 15 names a pre-rendered `…-filtered-N` copy to draw ([0284](../experiments/0284-image-adjustments.md)). Pages draws that copy and doesn't apply field 14 on opening; without field 15 it draws the original unadjusted (*confirmed* by writing them, [0412](../experiments/0412-writing-image-adjustments.md)). Remove Background leaves the image file alone: field 10 holds the subject's outline as a path in the image's pixels, field 22 is 1, and a mask crops to the subject ([0285](../experiments/0285-removed-background.md)). The outline in field 10 clips the image by itself, and so does the mask; fields 19 and 22 change nothing drawn (*confirmed* by writing them, [0446](../experiments/0446-writing-a-removed-background.md)). Image field 5 names a mask (type 3006): a drawable placed relative to the image, whose outline, in the path form of shapes, clips it; the image file itself isn't cropped ([0245](../experiments/0245-image-mask.md)). The mask's position (1.1.1) is from the image's corner, and its outline is drawn at the path's natural size (2.5.2), not the mask's own size (1.1.2), *confirmed* by writing them ([0390](../experiments/0390-writing-an-image-mask.md)).

## Text boxes and shapes

A text box's text is a text storage of its own, without field 1; writing its field 3 changes the box's text, *confirmed* ([0349](../experiments/0349-writing-text-in-a-box.md)). A text box, a shape and a line are all shapes of type 2011, listed by the same page-level record. A shape's position and size are in field 1.1, though a shape with a path is drawn at its path's natural size (1.3.5.2) whatever 1.1.2 says, *confirmed* by writing each ([0405](../experiments/0405-writing-a-shape-size.md)); its outline path is in 1.3 (either a path in 1.3.5, with a natural size in 5.2 and elements in 5.3.1 whose kind is 1 move, 2 line, 4 cubic curve (two control points, then the end point, [0218](../experiments/0218-oval.md)) or 5 close; or, once made editable, a list of nodes with control points in 1.3.8, [0217](../experiments/0217-editable-shape.md), a node *confirmed* by writing it and measuring, [0333](../experiments/0333-writing-a-path-point.md); or a parametric shape in 1.3.4: kind 0 a rounded rectangle with its radius, kind 1 a polygon with its number of sides, [0219](../experiments/0219-scalar-path-shapes.md); or one in 1.3.3 with a pair of numbers: kind 100 a star with its points and inner ratio, kind 1 an arrow with its head position and shaft thickness, [0220](../experiments/0220-point-path-shapes.md); or a callout in 1.3.6, with its box size in field 1 and corner radius in field 3, [0221](../experiments/0221-speech-bubble.md)) and its style (type 2025, such as `textbox-0-shapestyle`, `shape-0-shapestyle` or `line-0-shapestyle`) in 1.2. Fields 2 and 4 name its text, a type-2001 record with no field 1. *Likely* ([0049](../experiments/0049-text-box.md), [0050](../experiments/0050-shape.md), [0051](../experiments/0051-line.md)) A shape style keeps its properties one level deeper than text styles, in field 1.11; field 1.11.1.1 is the fill colour, in the same colour layout as text colour, and 1.11.3 the opacity. *Likely* ([0077](../experiments/0077-shape-fill.md), [0098](../experiments/0098-keynote-shape-opacity.md)); the fill colour and the stroke width 1.11.2.2, a stroke centred on the outline, are *confirmed* by writing them and measuring ([0330](../experiments/0330-writing-a-shape-fill-and-stroke.md)) The fill can hold a gradient in 1.11.1.2 instead of a colour: its kind in field 1 (0 linear, 1 radial, [0275](../experiments/0275-radial-gradient.md)), whether the advanced editor made it in field 4 ([0283](../experiments/0283-advanced-linear-gradient.md)), stops in its field 2 (each a colour, a position from 0 to 1 and a midpoint) and the angle in radians in 5.2, counter-clockwise from the right with y up, so 0 runs left to right and 270° top to bottom ([0260](../experiments/0260-gradient-fill.md); stop colours, positions and the angle *confirmed* by writing them, [0384](../experiments/0384-writing-a-gradient.md)). For a radial gradient the angle also places the centre: at 315°, the angle Pages uses, it is the middle of the shape, *confirmed* by writing it; field 4 changes nothing drawn ([0385](../experiments/0385-writing-a-radial-gradient.md)). In general the centre is C + d·(u(315°) − u(θ)), with C the box's centre, u(θ) = (cos θ, −sin θ) and d the width over 2√2 (*likely*, from eight angles in a square, [0444](../experiments/0444-where-a-radial-gradient-is-centred.md)); in a 200 × 100 shape that formula doesn't hold, though 315° still centres the gradient, so the general rule is *unknown* ([0445](../experiments/0445-a-radial-gradient-in-a-wide-shape.md)). Field 1.11.2 is the stroke: its colour in 2.1, its width in points in 2.2, and its pattern kind in 2.6.1, 1 for a solid line and 2 for none, as in the default style ([0250](../experiments/0250-shape-border.md)), or 0 for a dash pattern whose lengths are in 2.6.4, in multiples of the stroke width, the count used in 2.6.3 ([0274](../experiments/0274-dashed-border.md); *confirmed* by writing a pattern and measuring it, [0332](../experiments/0332-writing-a-dash-pattern.md)). Field 1.11.4 is the shadow: colour (1), angle in degrees in page coordinates, with y down (2, 90 for a shadow below; the sidebar shows 360° minus it, [0278](../experiments/0278-shadow-angle.md)), offset in points (3), blur (4), opacity (5) and whether it is shown (6) ([0251](../experiments/0251-shape-shadow.md); with the shape's opacity 1.11.3, *confirmed* by writing and measuring, [0331](../experiments/0331-writing-opacity-and-shadow.md)). The presets in the sidebar are named styles `shape-N-shapestyle` that shapes point at directly, *confirmed* ([0215](../experiments/0215-shape-style-preset.md); and by writing the reference, [0413](../experiments/0413-writing-a-shape-style-preset.md)).

## Groups

A group is a type-3008 drawable listing its members in field 2. Its geometry is the box around them; each member names the group in its field 1.2 and is positioned relative to the group's corner (*confirmed* by writing the group's position and a member's, [0372](../experiments/0372-writing-a-group.md); Pages then recomputes the group's box from its members). Only the group is listed on the page. *Likely* ([0216](../experiments/0216-group.md))

## Sounds and movies

Sounds and movies are type 3007. Field 14 names the media file by data ID, field 15 a poster image for a movie, field 7 the volume (0–1) and field 24 the repetition (0 none, 1 loop, 2 loop back and forth); both are *confirmed* by writing them into a sound and a movie ([0363](../experiments/0363-writing-media-volume-and-repetition.md)). Field 23 is 1 when the media has pictures and field 9 is 1 when it has only sound; fields 20 and 21 are a movie's natural size. Field 29 describes the first track: its kind (`soun` or `vide`) and time scale. A sound's drawable has a size of 0 × 0. *Likely* ([0185](../experiments/0185-keynote-audio.md)–[0187](../experiments/0187-keynote-movie.md)). Pages and Numbers store media in the same record: that sounds and movies are type 3007 with their file in field 14 is *confirmed* ([0188](../experiments/0188-media-in-pages-and-numbers.md)).

## Charts

A chart is a drawable of type 5021 on the slide. Its field 10000.7 holds its data: row names in 7.1, column names in 7.2, and one 7.3 per row listing its values as doubles. *Confirmed*: Pages stores charts the same way ([0067](../experiments/0067-chart.md), [0222](../experiments/0222-pages-chart.md)). A Numbers chart also links to its table: field 10000.8 names a type-12006 record whose field 3 holds formulas, in the cell-formula node form, for the series values (3.1), category labels (3.3) and series names (3.4); 10000.7 keeps a copy of the values. *Likely* ([0225](../experiments/0225-numbers-chart.md)). Numbers draws the chart from the formulas, evaluated on opening, and ignores the copy; a series is a range of two references joined by node 29 (*confirmed* by writing them, [0409](../experiments/0409-writing-a-numbers-chart-link.md)).

A chart also names a chart style (type 5022) in field 10000.9 and a type-5023 record of settings in 10000.10. In the settings, 10000.21 = 1 shows the chart's title and 10000.20 = 1 its legend; turning one off leaves 0. *Confirmed* by writing them ([0298](../experiments/0298-writing-chart-switches.md)). The border is chart style property 10000.18 = 1, which Keynote sets through an unnamed style whose parent is the theme's chart style, as with text styles (*confirmed* by writing it, [0399](../experiments/0399-writing-chart-border-and-axes.md)). A chart's caption is drawable field 1.11, as for other objects (its text *confirmed* by writing it; an empty caption isn't drawn in an exported slide, [0430](../experiments/0430-writing-a-chart-caption.md)). *Likely* ([0295](../experiments/0295-chart-options.md))

Each part of a chart has such a pair of a style and a settings record, named in field 10000: 10000.9 and 10000.10 the chart (types 5022, 5023), 10000.11 and 10000.12 types 5024 and 5025, 10000.13 and 10000.14 the value axes (types 5026, 5027, two each, the main value axis first), and 10000.15 and 10000.16 the category axis ([0297](../experiments/0297-chart-category-axis.md)). Field 10000.17 names six series styles (type 5028, `chart-0-series_0` and on; a series style's properties 6 to 17 are fills, one per kind of shape: 10000.13 for bars, 10000.11 for areas and 10000.17 for pie wedges, *confirmed* by writing them, the stroke property 10000.48 draws a line chart's line and 10000.53 the outline of a scatter chart's points, whose fill is *unknown*, and 10000.30 to 10000.34 are shadows, [0456](../experiments/0456-writing-a-series-colour.md), [0457](../experiments/0457-series-colours-by-chart-type.md), [0458](../experiments/0458-a-series-line-stroke.md), [0459](../experiments/0459-a-series-points.md)) and 10000.20 the chart's 25 paragraph styles (type 2022). Shareable properties go in a style, which Keynote overrides through an unnamed child style; a chart's own switches go in its settings record. For the value axis, style property 10000.25 = 1 draws the axis line and 10000.31 = 0 hides the minimum value, and setting 10000.14 = 1 shows the axis name (all three *confirmed* by writing them, drawing as Keynote's own pixel for pixel, [0399](../experiments/0399-writing-chart-border-and-axes.md)); the category axis shows its name with setting 10000.13 = 1 (*confirmed* by writing it; 10000.14 does nothing there, [0400](../experiments/0400-writing-a-category-axis-name.md)). *Likely* ([0296](../experiments/0296-chart-axis.md), [0297](../experiments/0297-chart-category-axis.md))

Writing the grid and the type changes the chart Keynote draws, *confirmed* in [0317](../experiments/0317-writing-chart-data.md). Field 10000.1 is the chart type and 10000.5 the grouping into series (1 by row, 2 by column, *confirmed* by writing it, [0350](../experiments/0350-writing-chart-grouping.md)); the data grid in 10000.7 is the same whatever the type or grouping. *Likely* ([0079](../experiments/0079-pie-chart.md)–[0086](../experiments/0086-chart-grouped-by-column.md))
