# 4. Tables

How tables are stored, in Pages, Keynote and Numbers alike: the table model, its tiles and cells, cell formats, formulas and merged cells. How a Numbers document reaches its tables from the root is in [Numbers](numbers.md#from-the-root-to-a-tables-cells), and Numbers' categories, filters and highlighting are there too. Every finding links to the experiments that support it, with a confidence level as defined in [CONTRIBUTING.md](../CONTRIBUTING.md#confidence). Records, object IDs and types are as described in [1. Container](container.md).

## From the text to the table

For a table, the attachment (type 2003, in `Document.iwa`) points at a drawable (type 6000, in `CalculationEngine`). The drawable holds the position and size in points (fields 1.1.1 and 1.1.2) and points at the table model (type 6001), whose fields 6, 7 and 8 are the number of rows, the number of columns and the table's name, and fields 9, 10 and 11 the numbers of header rows, header columns and footer rows (absent means 0; footer rows count within the rows, [0184](../experiments/0184-footer-row.md)), field 12 whether header rows are frozen ([0125](../experiments/0125-unfrozen-headers.md); fields 9 to 12 *confirmed* by writing them, [0301](../experiments/0301-writing-header-rows.md)) and field 13 whether header columns are ([0183](../experiments/0183-unfrozen-header-columns.md); *confirmed* by writing it, [0401](../experiments/0401-writing-frozen-header-columns.md)); field 29 is 1 when header rows repeat on each page ([0246](../experiments/0246-repeated-header-rows.md); *confirmed* by writing it both ways, [0402](../experiments/0402-writing-repeated-header-rows.md)). Rows, columns and name are *confirmed* ([0120](../experiments/0120-fewer-rows.md), [0122](../experiments/0122-table-name.md), [0123](../experiments/0123-fewer-columns.md)). A Numbers table's stored y is 28 points less than the y Numbers reports ([0126](../experiments/0126-table-at-origin.md)): the stored position is the corner of the whole object, and while the table's name is shown above it (model field 22), the body starts 28 points lower; with the name hidden the two are the same (*confirmed* by writing them, [0418](../experiments/0418-writing-a-table-position.md)). Sorting rewrites the rows ([0119](../experiments/0119-sorted-rows.md)), and so does transposing, which also swaps fields 6 and 7 ([0182](../experiments/0182-transposed-table.md)). *Likely* ([0020](../experiments/0020-a-table.md), [0060](../experiments/0060-header-rows.md)). A table's size is the sum of its row heights and column widths. The drawable's size can be out of date ([0059](../experiments/0059-table-geometry.md)).

## The table model's storage

The table model's field 4 holds its storage: 4.3 lists the tiles, each entry giving a tile index (4.3.1.1) and the tile record (4.3.1.2), and 4.1 and 4.2 name the row and column header storage buckets (type 6006). A bucket lists rows or columns with their own size in its repeated field 2: field 1 is the index, from 0, and field 2 the height or width in points as a float; unlisted rows and columns have the default size ([0045](../experiments/0045-row-and-column-sizes.md); *confirmed* by writing them, [0308](../experiments/0308-writing-row-and-column-sizes.md)). Each tile covers 256 rows (field 4.3.2), and row numbers inside a tile are local, so a cell's row in the table is the tile index × 256 plus its row in the tile. A tile's field 4 counts its rows with content, but Numbers reads the rows from the field-5 entries themselves and ignores the count, and field 6, which held the same number (*confirmed* by writing wrong counts, [0437](../experiments/0437-writing-a-tile-row-count.md)). *Likely* ([0029](../experiments/0029-numbers-root-to-table.md), [0030](../experiments/0030-tiles.md)), in Pages and Numbers alike. The row rule is *confirmed* ([0030](../experiments/0030-tiles.md), [0063](../experiments/0063-sparse-tiles.md)). Tiles without content are left out of the list, so a reader must use each entry's tile index. *Likely* ([0063](../experiments/0063-sparse-tiles.md))

## Rows in a tile

A table's cells are stored by row in its tile (type 6002, `Index/Tables/Tile.iwa`). Each row with content is one field-5 entry: 5.1 is the row index, 5.4 a table of 255 little-endian 16-bit offsets into the row's cell bytes (one per column, `ffff` for an empty cell), and 5.6 the cell bytes. A cell starts with a version byte (5) and a type byte: 2 for a number, stored as a little-endian IEEE 754 decimal128, and 3 for text, stored as a 32-bit key into a string table (type 6005, `Index/Tables/DataList.iwa`) whose entries hold the key in field 3.1, the number of cells using it in 3.2 and the string, as UTF-8, in 3.3 ([0113](../experiments/0113-shared-string.md), [0118](../experiments/0118-emoji-in-cell.md)). Equal texts share an entry, so changing an entry's string changes every cell using it (*confirmed* by writing it, [0306](../experiments/0306-writing-a-shared-string.md)), and unused entries are removed ([0114](../experiments/0114-cleared-cell.md)), and long texts are stored whole ([0130](../experiments/0130-long-text.md)). *Confirmed* ([0021](../experiments/0021-table-cells.md), [0026](../experiments/0026-numbers-cells.md)); all three apps store the same cells byte for byte, and keep formulas, merges and header counts the same way ([0131](../experiments/0131-pages-table-cells.md)–[0137](../experiments/0137-keynote-currency.md)).

When a row has several cells, it is field 5.7, not 5.4, that holds their byte offsets. *Likely* ([0031](../experiments/0031-cell-kinds.md))

## Cells

A cell's bytes 8–11 are little-endian flags saying which values and keys follow, in order of their bits. Further type bytes are 0 (no value, formatting only, [0138](../experiments/0138-empty-styled-cell.md)), 5 (date), 6 (boolean), 8 (a formula whose result is an error, stored with no value, [0078](../experiments/0078-formula-error.md)) and 10 (currency). *Likely* ([0031](../experiments/0031-cell-kinds.md))

| Flag bit | Followed by |
| --- | --- |
| 0x0001 | A decimal128 number |
| 0x0002 | A double, for a boolean (type 6): 1.0 is true and 0.0 false, for a checkbox or a formula's result (*confirmed* by writing one, [0338](../experiments/0338-writing-a-checkbox.md)) ([0036](../experiments/0036-more-cell-formats.md), [0169](../experiments/0169-unchecked-checkbox.md), [0175](../experiments/0175-boolean-formula.md)) |
| 0x0004 | A date, as a little-endian double: seconds since 2001-01-01 00:00, with the shown clock time counted as UTC (no time-zone conversion); *confirmed* by writing one ([0337](../experiments/0337-writing-a-date.md)) |
| 0x0200 | A key into the formula list (model field 4.6), whose entries are formulas as postfix lists of nodes |
| 0x0008 | A string key ([0021](../experiments/0021-table-cells.md)) |
| 0x0020 | A key into the style list (list type 4) naming a cell style: type 6004, background colour in field 11.1.1 (*confirmed* by writing it, [0309](../experiments/0309-writing-a-cell-colour.md)), text wrap in 11.3 (0 off, 1 on; *confirmed* by writing it, [0313](../experiments/0313-writing-alignment-and-wrap.md)) ([0043](../experiments/0043-cell-styles.md), [0062](../experiments/0062-text-wrap.md)) |
| 0x0040 | A key into the style list naming a text style: an unnamed paragraph style (type 2022) with the cell text's character properties and its alignment in 12.1 ([0043](../experiments/0043-cell-styles.md), [0061](../experiments/0061-cell-alignment.md); *confirmed* by writing it, [0313](../experiments/0313-writing-alignment-and-wrap.md)) |
| 0x0400 | A key into the cell-control list (list type 12). Its entry's field 12.1 is the control (4 stepper, 5 slider, 6 rating, 8 checkbox) and 12.3, 12.4 and 12.5 the minimum, maximum and step ([0036](../experiments/0036-more-cell-formats.md), [0169](../experiments/0169-unchecked-checkbox.md)–[0172](../experiments/0172-stepper.md)) |
| 0x1000 | A key into a list not identified yet (*unknown*) |
| 0x2000, 0x4000, 0x8000 | A key into the format list (model field 4.22), for a number, currency or date format |
| 0x10000, 0x20000, 0x40000 | A key into the format list, for a duration, text or boolean format ([0036](../experiments/0036-more-cell-formats.md)) |

## Formats

The format list's entries give the kind of format in field 1, which decides how the cells using it are shown (*confirmed* by writing 258 over 256, [0307](../experiments/0307-writing-a-format.md), and 259 and 267 in a sweep of kinds, [0323](../experiments/0323-format-kind-sweep.md)) (256 number, 257 currency, 258 percent, 259 scientific, 260 text, 261 date, 262 fraction, 263 checkbox, 267 rating, 268 duration, 269 numeral system ([0181](../experiments/0181-numeral-system.md)), whose field 8 is probably the base), plus its details, such as a currency code or a date pattern: field 2 is the number of decimal places, 253 for automatic ([0341](../experiments/0341-writing-decimal-places.md)), field 4 the negative style (0 minus sign, 1 red without a sign, 2 in parentheses, 3 red in parentheses, *confirmed* in [0343](../experiments/0343-negative-number-styles.md)) and field 5 the thousands separator ([0342](../experiments/0342-negative-numbers-and-thousands.md)); for a currency, field 3 is the ISO 4217 code (*confirmed* by writing them, [0339](../experiments/0339-writing-a-currency-format.md)); for a date, field 14 is the pattern in Unicode date-pattern syntax, such as `dd.MM.y HH:mm` (*confirmed*, [0340](../experiments/0340-writing-a-date-pattern.md)). A formula cell also keeps its last result as a value, as a cell of the result's type: a date, or text through the string table ([0108](../experiments/0108-today.md), [0110](../experiments/0110-text-result.md)). Writing a new decimal128 in place of a cell's value changes the cell, so nothing else caches it ([0290](../experiments/0290-writing-a-cell.md)). A negative decimal128 has its sign bit set, *confirmed* ([0112](../experiments/0112-unary-minus.md), [0174](../experiments/0174-negative-number.md)). Text that looks like a number is stored as a number unless the cell's format is text ([0176](../experiments/0176-number-as-text.md)). *Likely* ([0031](../experiments/0031-cell-kinds.md))

## Merged cells

Merged cells are recorded in the table model's field 47.2, as ranges in this node form, not in the cells. In each range's first node, field 40.3 is the span of columns and 40.4 the span of rows, each { 1: first, 2: last } counted from 0, with a missing last meaning a span of one: 40.3 = { 1: 2 } and 40.4 = { 1: 1, 2: 2 } is C2:C3 (*confirmed* by writing them, [0382](../experiments/0382-writing-merged-cells.md)). A merged cell keeps its value in its top-left cell. *Likely* ([0044](../experiments/0044-merged-cells.md)). Numbers also shows a value stored in another cell of the range when the top-left is empty, and gives the merged cell the top-left cell's look (*confirmed* by writing it, [0426](../experiments/0426-writing-a-merge-over-a-value.md)).
