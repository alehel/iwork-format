0324: Writing text columns, measured on the page#

App release: 15.4

Status: run

0254 found a body's columns in a column style (type 2024), named by the text's field-12 runs: property 11.7.1 holds the number of columns in field 1 and the gap in field 2. This experiment writes two columns into a one-column document and measures the lines on the exported page with recipes/0319-measure-pdf.swift, which now also lists each line's separate pieces.

Setup#

Pages15.4
macOS26.5.2 (25F84)
Date2026-11-10
Inputsamples/0320/long.pages: one paragraph wrapping to several lines, whose column style is record 1732607, an unnamed child of the None column style with no columns of its own
Writerrecipes/0302-set-path.py

Recipe#

mkdir -p samples/0324
cp samples/0320/long.pages samples/0324/one.pages
python3 -I recipes/0302-set-path.py samples/0324/one.pages samples/0324/two.pages 1732607 11.7.1.1 varint 2 11.7.1.2 float 0.05

The values are those 0254 found for Pages' own two columns. Each file was opened in Pages on its own, exported as PDF and measured.

Observation#

FileFirst lines, left to right
one.pages57.5 – 506.0
two.pages57.5 – 279.8

The text area is 481.9 points wide. With a gap of 0.05 of that, 24.1 points, each of two columns is 228.9 points wide, so the first column ends at 285.6. The paragraph fits in the first column, so the second stays empty.

Conclusion#

11.7.1.1 is the number of columns and 11.7.1.2 the gap between them, as a fraction of the text area's width; the lines wrap to the first column's width, which these values give.

Evidence#

2021#5 11.1: 0 → 1 says that field 11.1 of the type-2021 record with ID 5 held 0 and holds 1; without an ID, that some record of the type does. = is a value it holds, ≠ one it doesn't, ~ bytes it contains, and ×2 how often a field occurs. These statements were checked against the documents by script (fixtures/evidence.py); only means that nothing else differs but the previews. What the app showed, and what follows from it, is the experiment's own.
