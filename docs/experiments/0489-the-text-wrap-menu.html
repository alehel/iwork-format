0489: The text wrap menu, and Inline with Text#

App release: 16.0

Status: run

Writing drawable field 1.3 showed it to be the text wrap (0488), but the values could only be matched to what was drawn, not to the names Pages gives them, and Inline with Text couldn't be chosen in the background (0487). This experiment chooses each entry of the Arrange sidebar's wrap menu, the Text Fit buttons and the alpha, saving after each, and then sets the picture to Move with Text and Inline with Text.

Setup#

Pages16.0 (7052.0.68), with a Norwegian (nb) user interface
macOS26.5.2 (25F84)
Date2026-11-28
Input0487/stay.pages: a two-line paragraph and the red picture of 0023 at 80 × 40 points on page 1, Stay on Page, with Pages' default wrap { 1: 4, 2: 2, 3: 1, 4: 12.0, 5: 0.5, 6: 0 }
RecipeIn the Pages window, by hand (computer use with the window in front), each step saved with AppleScript's save front document in

Recipe#

  1. Copy 0487/stay.pages to samples/0489/work.pages, open it with open -a "Pages Creator Studio", select the picture and open the Arrange (Ordne) tab. The wrap menu (Tekstbryting) shows Automatisk and offers Automatisk, Rundt, Over og under and Ingen (Automatic, Around, Above and Below, None). It has no choice of sides.
  2. Choose Rundt (Around); save as around.pages.
  3. Choose Ingen (None); save as none.pages. Spacing and alpha grey out.
  4. Choose Over og under (Above and Below); save as above-and-below.pages.
  5. Choose Rundt again and the first Text Fit (Tekstflyt) button; the alpha field greys out. Save as around-box-fit.pages.
  6. Choose the second Text Fit button and type 70 in the alpha (Alfa) field; save as alpha-70.pages.
  7. Click Flytt med tekst (Move with Text). The wrap menu now has a fifth entry, Bundet til teksten (Inline with Text), between Over og under and Ingen. Save as move-around.pages.
  8. Choose Bundet til teksten. The picture moved onto the paragraph's second line, after once., and the line grew to its height; position, Text Fit, spacing and alpha grey out. Save as inline.pages. Close work.pages unsaved and delete it.

Conclusion#

The wrap menu's entries are 1.3.1 = 4 Automatic, 1 Around, 2 Above and Below and 5 None, and for an object that moves with the text, 0 Inline with Text. The menu has no choice of sides, so Pages always writes 1.3.2 = 2 (both); the other sides of 0488 can only be written. Wrap 3, which 0488 drew on one side, isn't offered.

The first Text Fit button, which greys out the alpha, writes 1.3.3 = 0, and the second, Pages' default, 1: box and outline fit. The alpha field is 1.3.5, as a fraction.

Inline with Text is not a third kind of anchor: it is a Move with Text attachment whose wrap is 0. Pages takes such an object out of the page's stacking list (type 10015), since it is drawn in the line, and leaves its offset and position in the file unused. 0490 tests this by writing.

Evidence#

2021#5 11.1: 0 → 1 says that field 11.1 of the type-2021 record with ID 5 held 0 and holds 1; without an ID, that some record of the type does. = is a value it holds, ≠ one it doesn't, ~ bytes it contains, and ×2 how often a field occurs. These statements were checked against the documents by script (fixtures/evidence.py); only means that nothing else differs but the previews. Confidence#

Confirmed, by the sidebar here and by drawing in 0488: 1.3.1 = 1 Around, 2 Above and Below, 5 None, 4 Automatic (Pages' default), and 1.3.3 = 0 box fit, 1 outline fit.

Likely: 1.3.5 is the alpha threshold, and Inline with Text is 1.3.1 = 0 on an attached object, which 0490 confirms by writing.
