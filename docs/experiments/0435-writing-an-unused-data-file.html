0435: Writing a data file that nothing uses#

App release: 15.4

Status: run

Files nothing uses are dropped on save (0145): when an image was deleted, its file and its entry in Metadata.iwa record 2 went with it. This experiment adds a file that no record uses, with and without an entry, and has Pages save the document.

Setup#

Pages15.4
macOS26.5.2 (25F84)
Date2026-11-18
Inputsamples/0023/image.pages: one image, data ID 24, stored as Data/red-8x4-24.png; record 2 lists data IDs 8, 9, 14, 23 (the template's resources) and 24. The added file is the green 8 × 4 PNG of 0395
WriterThe new [recipes/0435-add-data.py](../recipes/0435-add-data.py); saved with [recipes/0372-in-app.sh](../recipes/0372-in-app.sh)

Recipe#

mkdir -p samples/0435
O=samples/0435
cp samples/0395/green-8x4.png $O/green.png
python3 -I recipes/0435-add-data.py samples/0023/image.pages $O/extra-listed.pages 99 $O/green.png
python3 -I recipes/0435-add-data.py samples/0023/image.pages $O/extra-unlisted.pages 99 $O/green.png --no-entry
for f in extra-listed extra-unlisted; do
  sh recipes/0372-in-app.sh Pages $O/$f.pages "save d in POSIX file \"$PWD/$O/$f-saved.pages\""
  unzip -l $O/$f-saved.pages | grep Data/
done

Both written files store Data/green-99.png; extra-listed.pages also lists it in record 2 as data ID 99 with its SHA-1 and names.

Observation#

FileWrittenOpensSaved copy's Data/Saved copy's data IDs
extra-listed.pagesfile and entry 99yes, onered-8x4-24.png8, 9, 14, 23, 24
extra-unlisted.pagesfile onlyyes, onered-8x4-24.png8, 9, 14, 23, 24

Conclusion#

Pages opens a document with data nothing uses, listed or not, and drops it when it saves: both the file and its entry are gone. What it keeps is what the records use, as listed in their headers' field 2.6 (0397) and the template's resources. So a reader can ignore files no record names, and a writer doesn't need to tidy up after itself for Pages' sake.

Confidence#

Confirmed: Pages drops unused data files and their entries on saving, and opens documents that have them, by writing them.
