0482: Objects on later pages#

App release: 16.0

Status: run

So far every object placed on the page ("Stay on Page") was on page 1. There, a type-10015 record lists it next to the body's text, and a type-10010 record lists it as 1: { 1: 0, 4: { 1: { 1: <id> } } }, with a meaning not yet known (0023). This experiment places pictures on pages 2 and 3 of a three-page document, and on page 1 for comparison, to see how a page is recorded.

Setup#

Pages16.0 (7052.0.68)
macOS26.5.2 (25F84)
Date2026-11-28
Inputthree-pages.pages: samples/0002/hello.pages with the body text written as one, U+0005, two, U+0005, three, so that it has three pages (0018). AppleScript can't make a page break: Pages drops U+0005 from a body text set by script
Reciperecipes/0482-place-on-pages.sh opens a document, places the 8 × 4 red picture of 0023 on each page it is given, in that order, and saves a copy. Exported with recipes/0372-in-app.sh and checked with recipes/0482-red-per-page.swift, which says on which page of a PDF red is drawn, and where

Pages reported three pages for each document. In every one, the first picture placed is 1732688 and the second 1732695.

Observation#

The two records#

In all five documents the root (object 1, type 10000) names record 1732278, type 10010, in field 3 and record 1732364, type 10015, in field 20, as it does in 0023/image.pages.

Record 1732364 (type 10015) always lists the body's text, then the pictures in the order they were placed:

1: { 1: 1732539 }   1: { 1: 1732688 }   1: { 1: 1732695 }

Record 1732278 (type 10010) has one field-1 entry for each page that has a picture:

on-2-and-3.pages2, 3{ 1: 1, 4: { 1: { 1: 1732688 } } }, { 1: 2, 4: { 1: { 1: 1732695 } } }
on-1-and-1.pages1, 1{ 1: 0, 4: { 1: { 1: 1732688 } }, 4: { 1: { 1: 1732695 } } }
on-2-and-2.pages2, 2{ 1: 1, 4: { 1: { 1: 1732688 } }, 4: { 1: { 1: 1732695 } } }
on-3-then-2.pages3, then 2{ 1: 1, 4: { 1: { 1: 1732695 } } }, { 1: 2, 4: { 1: { 1: 1732688 } } }
on-1-and-3.pages1, 3{ 1: 0, 4: { 1: { 1: 1732688 } } }, { 1: 2, 4: { 1: { 1: 1732695 } } }

The pictures' positions#

Both pictures in on-2-and-3.pages are at about the same place, 1.1.1 = (286.8, 397.71) and (286.8, 397.51), the middle of an A4 page (595.28 × 841.89). In the PDF, page 2 has red at (286.8, 397.5)–(295.0, 401.8) and page 3 at (286.8, 397.2)–(295.0, 401.5), in points from each page's top-left corner. Page 1 has none.

Conclusion#

Type 10010 is the list of the pages that have objects placed on them. Each entry of its field 1 is one page: 1.1 is the page's number, counting from 0 for the document's first page, and each 1.4 names one object on it (4.1.1). A page with no placed object has no entry, so page 1 of on-2-and-3.pages is missing. Entries are in page order, whatever order the objects were placed in. Objects on the same page share one entry, with one field 4 each, in the order they were placed.

Type 10015 stays a single list for the whole document, whatever page an object is on: the body's text and every placed object, back to front (0425). An object on page 3 is in it like one on page 1, and the body's text is first in a document made by placing objects on a page.

An object's position (drawable field 1.1.1) is measured from the top-left corner of its own page, not of the document: both pictures sit at y ≈ 397.6 though one is a page lower.

The root (type 10000) names the 10010 record in field 3 and the 10015 record in field 20.

Evidence#

2021#5 11.1: 0 → 1 says that field 11.1 of the type-2021 record with ID 5 held 0 and holds 1; without an ID, that some record of the type does. = is a value it holds, ≠ one it doesn't, ~ bytes it contains, and ×2 how often a field occurs. These statements were checked against the documents by script (fixtures/evidence.py); only means that nothing else differs but the previews. Confidence#

Confirmed: the root's field 3 names the type-10010 record and field 20 the type-10015 record (this experiment and 0023). The page numbers, the position measured from the object's own page and the page order of the entries are confirmed by writing them in 0484, and the numbering across sections in 0486.

Likely: the rest of the reading of type 10010 above, and that 10015 is one list for the whole document.
