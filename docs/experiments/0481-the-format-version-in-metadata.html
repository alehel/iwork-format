0481: The format version in Metadata.iwa#

Status: run

The comparisons between releases (0461, 0473, 0476) list the top-level fields each record type uses, not what nested messages or packed values hold. Before the spec moves to describing 16.0, this experiment looks one step further for anything they missed. Comparing the nested fields of the published samples between releases found one: field 7 of the package metadata record, type 11006 in Index/Metadata.iwa, whose bytes differ in every release.

Setup#

ToolNo app: the new recipes/0481-format-version.py, which reads field 7 as packed varints and compares it with fileFormatVersion in Properties.plist, and checks each copy's last build against the release its folder names
Date2026-11-25
InputEvery .pages, .numbers and .key in samples/, the sets for each release and the resaved copies included: 6,140 documents that aren't encrypted

Recipe#

python3 -I recipes/0481-format-version.py samples

Observation#

Field 7 is the file format version, as packed varints:

ReleaseField 7, bytesReadfileFormatVersion
16.01b 00 0127, 0, 127.0.1
15.41a 04 0026, 4, 026.4.0
14.50e 04 0114, 4, 114.4.1
13.10d 01 0213, 1, 213.1.2

It equals fileFormatVersion in all 6,140 documents, in all three apps and in folder packages. The 31 documents that couldn't be read are encrypted.

The last row is a mistake in 0476: its 14.5 copies were saved by the installed 16.0 apps. recipes/0372-in-app.sh opens "Pages Creator Studio" and so on when they are installed, and they were, whatever else was running. 0476 is corrected, and recipes/0476-resave.py now counts a copy as failed when the release that saved it isn't the one named.

The nested comparison found no other field that only one release writes, apart from those already listed on the releases page. It covers which fields are present, not all their values.

Conclusion#

Metadata.iwa repeats the file format version, so a reader of the records alone can tell it. What the app does with it on opening, and whether a writer that changes one has to change the other, is unknown.

Every set of samples was saved by the release it is named for, except the copies 0476 called 14.5's.

Evidence#

No documents of its own: it reads the metadata of every document under samples/. One from each release:

2021#5 11.1: 0 → 1 says that field 11.1 of the type-2021 record with ID 5 held 0 and holds 1; without an ID, that some record of the type does. = is a value it holds, ≠ one it doesn't, ~ bytes it contains, and ×2 how often a field occurs. These statements were checked against the documents by script (fixtures/evidence.py); only means that nothing else differs but the previews. What the app showed, and what follows from it, is the experiment's own.
