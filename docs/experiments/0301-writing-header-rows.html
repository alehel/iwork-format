0301: Writing a table's header and footer rows#

Status: run

The table model's fields 9 to 13 were read as the numbers of header rows, header columns and footer rows, and whether header rows and columns are frozen (0120, 0125, 0183, 0184). Numbers' AppleScript can read all five. This experiment writes new values into a file and asks Numbers.

Setup#

Numbers15.4
macOS26.5.2 (25F84)
Date2026-11-10
Inputsamples/0226/plain.numbers: one table of 22 rows and 7 columns, with one header row and one header column, both frozen
Writer[recipes/0300-set-field.py](../recipes/0300-set-field.py), using the writer of 0287

Recipe#

mkdir -p samples/0301
python3 -I recipes/0300-set-field.py samples/0226/plain.numbers samples/0301/headers.numbers 6001 9=2 10=0 11=1 12=0

The table model (type 6001) had fields 9 = 1, 10 = 1 and 12 = 1, and no field 11. The script sets 2 header rows, 0 header columns, 1 footer row and unfrozen header rows, leaving field 13 (header columns frozen) at 1. Numbers then opened each file on its own, read the table's properties through AppleScript, and saved the written file again.

The first attempt opened the original first and then the written file: Numbers said the written file couldn't be opened at the moment, because the operation wasn't permitted, while the original was still open. The written file is a copy of the original and shares its document ID (container.md). Opened alone, it worked.

Observation#

OriginalWritten
header row count12
header column count10
footer row count01
header rows frozentruefalse
header columns frozentruetrue
row count2222

Saved again by Numbers, the model has fields 9 = 2, 11 = 1 and 13 = 1, and no fields 10 and 12: Numbers leaves out the fields that are 0.

Conclusion#

Fields 9, 10, 11 and 12 of the table model are what they were read as: header rows, header columns, footer rows, and whether header rows are frozen. Numbers writes a 0 in them by leaving the field out, so a reader must take an absent field as 0.

The apps seem to refuse to open a document while another with the same document ID is open, which explains failures seen with copies in 0299. Writers that start from a copy, and experiments that open both, should open one at a time. Likely, from three cases.

Confidence#

Confirmed: table model fields 9 to 12, by writing them.

Likely: the apps won't open two documents with the same document ID at once.
