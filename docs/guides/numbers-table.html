Reading a Numbers table#

This page decodes the cells of a small spreadsheet. It assumes the container layer from Reading a Pages document: parts, chunks, records and references are the same in all three apps.

The file is kinds-and-numbers.numbers, from experiment 0226: a new spreadsheet whose first table has a header row kind, n and four rows below it.

A tile's rows#

A tile (type 6002) has one field-5 entry per row with content. Each entry gives the row index (5.1), a table of 16-bit little-endian offsets, one per column, with ffff for an empty cell (5.7, or 5.4 in a row with a single cell), and the cell bytes (5.6) (text.md). A number cell#

Row 1, column 1 holds the number 1:

05 02 00 00 00 00 00 00   01 30 00 00   01 00 00 00 00 00 00 00 00 00 00 00 00 00 40 30   01 00 00 00   02 00 00 00
└ version, type 2 ┘       └ flags ┘     └ decimal128: 1 ──────────────────────────────┘   └ key 1 ┘     └ key 2 ┘
BytesMeaning
05Version 5
02Cell type 2, a number
01 30 00 00Flags 0x3001: bit 0x0001 (a decimal128 follows), 0x1000 (a key into a list not yet identified) and 0x2000 (a key into the format list, for a number format)
16 bytesThe value, an IEEE 754 decimal128, little-endian. The coefficient is in the low bits, here 1. The top two bytes 40 30 read as 0x3040 hold the sign (0) and the exponent 0x3040 >> 1 = 6176, which is the bias, so the exponent is 0. The value is 1 × 10⁰.
01 00 00 00The key for flag 0x1000
02 00 00 00The key for flag 0x2000: format 2

The values and keys follow in the order of their flag bits. The flag table in text.md lists the bits found so far.

Each entry in field 3 has its key (3.1), the number of cells using it (3.2) and the string as UTF-8 (3.3). a and b are each used by two cells, so equal texts share an entry. Rows 2 and 4 refer to key 4, b.

Key 1 is format kind 260, text, used by 6 cells: the two headers and the four letters. Key 2 is kind 256, a number, used by the four numbers (text.md).

A reader's steps#

  1. From the model, read the rows and columns (6, 7) and the tiles (4.3).
  2. For each tile, for each row entry: the table row is the tile index × 256 + the row index.
  3. For each column whose offset isn't ffff, read the cell: type byte, flags, then the values and keys in flag order.
  4. Look up strings in the string table (4.4) and formats in the format list (4.22).

Pages and Keynote tables are stored the same way, byte for byte (0131).
