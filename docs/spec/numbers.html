Numbers#

What is specific to Numbers documents. The container is the same as Pages' (container.md), and tables are stored as described in text.md. Every finding links to the experiments that support it, with a confidence level as defined in CONTRIBUTING.md.

Observed with Numbers 15.4 on macOS 26.5.2.

Parts#

A new spreadsheet has the seven .iwa parts that Pages documents have, without numbers in their names. It also has the table parts under Index/Tables/, because a new spreadsheet holds an empty table. Those are named as in Pages (see container.md), including some with a -2 ending. Likely (0024, 0026, 0030)

Categories#

Grouping rows by a column's values (Organise → Add Category) moves no cells. The groups are a tree of type-6383 records in CalculationEngine.iwa: each group has a 128-bit ID (field 1), its value as a typed cell value (field 6), its rows (field 9, single row numbers { 1: n } or ranges { 1: first, 2: last }) and its child groups (field 10). Table model field 81.2.6 becomes 1. The summary rows Numbers shows aren't stored. Likely (0226)

Pivot tables#

A pivot table is an ordinary table model whose cells hold the current summary, so it reads like any table. Numbers also adds a hidden table model with a copy of the source data, named after the source with as Pivot Source Table, and new record types (6369, 6370, 6374, 6382). Type 6370 names the source table in field 12 and holds the last update time in field 9. Its field 3 lists the row fields and field 5 the value fields, each with a summary function code in 5.1.3 (2 sum, 18 average), its own list rather than formula function numbers (0279). Likely (0227)

Filters#

A filter doesn't change any cells. Its rule is a formula in the node form of cell formulas, comparing the tested cell with a value (cell > 2 is a reference, the number 2 and comparison node 7), held in type-6220 records. The rows the filter hides are listed by their IDs in table model field 70.2.3, each with field 3 set to 1. Likely (0258)

Conditional highlighting#

A highlighting rule is a type-6010 record in the table's list of type 9. Its condition is a formula, as for filters, starting with node type 63, which probably stands for the cell being tested. It names a cell style (type 6004) and a text style (type 2022) to apply, both kept in ObjectContainer.iwa. Cells under the rule gain flag bits 0x80 and 0x100. Flag 0x80's key is the cell's entry in the type-9 list, and flag 0x100's key caches the result: the index of the first matching rule, from 0, or 15 when none matches, confirmed (0267, 0280). Likely (0259)
