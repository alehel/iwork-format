Numbers#

What is specific to Numbers documents. The container is the same as Pages' (container.md), and tables are stored as described in 4. Tables. Every finding links to the experiments that support it, with a confidence level as defined in CONTRIBUTING.md.

Observed with Numbers 15.4 on macOS 26.5.2.

Parts#

A new spreadsheet has the seven .iwa parts that Pages documents have, without numbers in their names. It also has the table parts under Index/Tables/, because a new spreadsheet holds an empty table. Those are named as in Pages (see container.md), including some with a -2 ending. Likely (0024, 0026, 0030)

Categories#

Grouping rows by a column's values (Organise → Add Category) moves no cells. The groups are a tree of type-6383 records in CalculationEngine.iwa: each group has a 128-bit ID (field 1), its value as a typed cell value (field 6), its rows (field 9, single row numbers { 1: n } or ranges { 1: first, 2: last }) and its child groups (field 10). Table model field 81.2.6 becomes 1. The summary rows Numbers shows aren't stored. Likely (0226). Numbers draws the groups from the tree as stored, without regrouping on opening: a group's heading is the value in its field 7 (the same value is in field 6, with the rows again, which alone doesn't change the heading), and its rows are those in field 9, confirmed by writing them (0411).

Pivot tables#

A pivot table is an ordinary table model whose cells hold the current summary, so it reads like any table: Numbers shows those cells as stored, and doesn't recompute them on opening or when the source changes, only when refreshed (confirmed by writing its summary function, 0410). Numbers also adds a hidden table model with a copy of the source data, named after the source with as Pivot Source Table, and new record types (6369, 6370, 6374, 6382). Type 6370 names the source table in field 12 and holds the last update time in field 9. Its field 3 lists the row fields and field 5 the value fields, each with a summary function code in 5.1.3 (2 sum, 18 average), its own list rather than formula function numbers (0279). Likely (0227)

Filters#

A filter doesn't change any cells. Its rule is a formula in the node form of cell formulas, comparing the tested cell with a value (cell > 2 is a reference, the number 2 and comparison node 7), held in type-6220 records. The rows the filter hides are listed by their IDs in table model field 70.2.3, each with field 3 set to 1. Likely (0258). Both are only what the rules editor shows and a cache: Numbers evaluates the filter when it opens a document, so clearing every hidden flag, or rewriting the value in the formulas, changes nothing (0383). The value it compares with is the varint in 905584's field 7.1.5.2.2, beside the same value as a double in 7.1.5.2.1; writing it changes the rows shown, confirmed (0391).

Conditional highlighting#

A highlighting rule is a type-6010 record in the table's list of type 9. Its condition is a formula, as for filters, starting with node type 63, which probably stands for the cell being tested. It names a cell style (type 6004) and a text style (type 2022) to apply, both kept in ObjectContainer.iwa (the cell style's fill and the text style's colour confirmed by writing them, 0453). Cells under the rule gain flag bits 0x80 and 0x100. Flag 0x80's key is the cell's entry in the type-9 list, and flag 0x100's key caches the result: the index of the first matching rule, from 0, or 15 when none matches, confirmed (0267, 0280). Numbers recomputes that cache when it opens a document, and it compares, by the kind in 3.1.1.1 (7 greater than, 8 greater than or equal, 9 less than, 10 less than or equal, confirmed by writing them, 0454), with the varint in the rule's field 3.1.1.5.2.2, not the value in the rule's formulas or the double in 3.1.1.5.2.1, confirmed by writing each (0391). Likely (0259)

The calculation engine#

All three apps keep a calculation engine in CalculationEngine.iwa, rooted in a type-4000 record whose field 17, when present, is the engine's UUID: it is absent from most new documents, and whether a document has it varies from one run of the same recipe to the next, as does the number of owners below (0469). 15.4 and 16.0 The 15.4 and 16.0 apps also give it an empty type-4011 record, named by its field 15, which 14.5 doesn't write (0461, 0469). 15.4 only Numbers 15.4's template also has one paragraph style that 14.5's and 16.0's lack, text-12-paragraphstyle-Table Title 1 (0464, 0469). It lists type-4008 records, one per owner: something that can take part in formulas. An owner's field 1 is its UUID, field 2 the number the engine knows it by, field 12 the engine's UUID, and field 13.1 names a type-4009 list. A type-4009 list's field 1 always repeats its owner's number (confirmed, 1,215 pairs in 565 documents). These records hold no cells, values or formulas, so a reader can skip them. How many owners there are, and their numbers, depend on the document's history and its theme. Most owners belong to tables: each table registers one for itself, named by its drawable's field 8 and its filter's row list (model field 70), one for its filter's rules, one for its categories, named by its drawable's field 7 and model field 81.2.1, and others named by model fields 84 and 93 and a type-6316 record; a type-6366 record names one in every document. Pivot formulas, highlighting rules and filters name owners too (confirmed where they are named, across 1,139 documents; what each stands for is likely, 0442). Likely (0293)
