Releases#

The specification describes the file format as the 15.4 apps write it. Other releases checked against it write the same format, with the few differences listed below; a statement that holds for some releases only carries a mark such as 15.4 only where it stands in the spec.

  • 15.4 is the release the spec describes, from 0001 on. Its apps are named "Pages Creator Studio" and so on.
  • 14.5 writes the same format (0461, 0464), opens and reads the 15.4 samples (0462) and draws them the same (0463).
  • 16.0 writes the same format too (0469), and where 14.5 and 15.4 differ it sides with 15.4, apart from Numbers' Table Title 1 style, which it leaves out as 14.5 does. What is new is one more field in each app's view-state record, which a reader can ignore. Its apps are named "Pages Creator Studio" and so on, as 15.4's were, and they replaced both 15.4 and 14.5 on the Mac the experiments run on, so documents can't be taken back to those releases.
  • Keynote 14.5 writes the same format too (0466), apart from a slide-node field, a resource and its Basic White template; it opens and reads the 15.4 presentations (0467) and draws them the same (0468). It doesn't know the radial wipe transition.

Telling which release saved a document#

Metadata/Properties.plist holds the file format version in fileFormatVersion, and Metadata/BuildVersionHistory.plist lists the template and the build of the app that saved it, such as M14.5-7045.0.17-4. The format version doesn't follow the app's version: 14.5 writes 14.4.1, 15.4 writes 26.4.0 and 16.0 writes 27.0.1 (0461). A reader doesn't need either to read a document, but they say which differences below can apply. Every sample document's build was checked against the release its experiment names, and all matched (0465).

Releases that change the format#

When a release writes a format that differs in more than a few details, the spec moves on to describe it, and the spec as it stood is kept for documents the earlier release wrote: python3 -I site/archive.py RELEASE freezes it in spec/versions/RELEASE/, and the site shows a Spec version menu to switch between them. No release has needed that yet.
