1. Container#

How a Pages document is packaged, and how its parts are encoded. Every finding links to the experiments that support it, with a confidence level as defined in CONTRIBUTING.md.

Observed with Pages 15.4 on macOS 26.5.2. Keynote 15.4 and Numbers 15.4 write the same container: the package, chunk, record and reference findings below hold for their documents too (0024). The apps differ in their document root (object 1: type 10000 in Pages, type 1 in Keynote and Numbers) and in the parts they add, such as Slide-N and TemplateSlide-N in Keynote.

The package#

A document saved by Pages is a ZIP file by default. Likely (0001, 0002). It can also be a folder (File → Advanced → Change File Type → Package): the metadata files and previews are files in the folder, the .iwa parts are inside an Index.zip in it, under the same Index/ names, and data files are in a Data/ folder beside it. Confirmed for all three apps (0076, 0146, 0147)

ZIP entry names are UTF-8, but Pages doesn't set the ZIP flag that says so; read them as UTF-8 regardless. Likely (0144)

Part names aren't fixed: after a document is saved again, a part can be renamed after the ID of its new first record (ViewState.iwa became ViewState-1732662.iwa). Find parts by listing them. Likely (0139)

Its entries are stored without ZIP compression. Confirmed (0001, 0002)

A new document holds these 13 parts. Confirmed (0001, 0002)

PartHolds
Index/*.iwa (seven parts)The document's objects, encoded as below
Metadata/DocumentIdentifierA UUID as 36 ASCII characters, with no line ending
Metadata/Properties.plistA binary property list of UUIDs, a file format version and flags
Metadata/BuildVersionHistory.plistA list of strings naming the template and the Pages build
preview.jpg, preview-web.jpg, preview-micro.jpgJPEG previews of the first page

The seven .iwa parts of a new document are AnnotationAuthorStorage-N, CalculationEngine-N, Document, DocumentMetadata, DocumentStylesheet, Metadata and ViewState. Where a name ends in a number, it is the ID of the part's first object. Confirmed (0001, 0002)

A document with a table also has parts under Index/Tables/: DataList, HeaderStorageBucket and Tile, each holding one record. Each is named Name.iwa, Name-N.iwa or Name-N-2.iwa, where N is the ID of the record inside. Both Pages and Numbers use all three forms. What the -2 ending means is unknown. Likely (0020, 0026, 0030)

Data files#

Files a document embeds, such as images, are stored unchanged under Data/, each named after its original file name with -N before the extension. N is a data ID, by which records refer to the file. Likely (0023)

Identical files are stored once (0142), in their original format (0143), and files nothing uses are dropped on save (0145). For a large image, Pages also stores a reduced copy (name-small-N.ext), which the image record names in field 12 (0148). Keynote does the same, with the copy at most 256 pixels on the longer side, and stores an image used twice once (0291). Likely

Metadata.iwa record 2 (type 11006) lists the data in its repeated field 4. Each entry holds the data ID (field 1), the file's SHA-1 (field 2), the original file name (field 3) and the stored file name (field 4). Entries for resources of the template have no file in the package. Likely (0023)

In Keynote, a theme's own photos are such entries: field 4 (the stored name) is empty, field 5 is a path to the resource inside the app, such as 21_basicwhite/910457886_1434x1669, Only a reduced copy, at most 256 pixels on the longer side, is stored in Data/, with its own entry, whose field 18 is the file's size in bytes. In every image's entry, stored or not, field 10.100.1 is the image's size in pixels: a message with the width in field 1 and the height in field 2, as floats.

Each data entry kept as an app resource, and only those, also has a colour: a type-11015 record in Metadata.iwa lists entries of a data ID (field 1) and a type-11014 colour (field 2), whose field 1 is RGB (1.1 = 1) with red, green, blue and alpha as floats in 1.3 to 1.6. Confirmed for 2,537 entries in 565 documents. The colour isn't the image's average; what it is for is unknown. (0294) Likely (0292)

Chunks#

An .iwa part is a sequence of chunks, with nothing before, between or after them. Confirmed (0001, 0002)

BytesHolds
1Chunk type. Always 0 so far.
3Length of the data that follows, little-endian
lengthA raw Snappy block (the block format, not the Snappy framing format)

Pages accepts any valid raw Snappy block, including one made only of literal runs, so a writer need not compress: a document whose parts were re-encoded that way opens and saves normally. Confirmed (0287)

No chunk has decoded to more than 65,536 bytes, and a part that decodes to more is split into chunks of exactly 65,536 decoded bytes, then a shorter last one. Confirmed (0001, 0141)

Records#

Decode every chunk and join the results in order. The joined bytes are a sequence of records, with nothing between them. A record can start in one chunk and end in the next, so the chunks have to be joined first. Confirmed (0001, 0002)

HoldsEncoding
Header lengthVarint
HeaderProtocol Buffers message of that length
PayloadsOne after another, one per header field 2, in the order those fields appear

The header's fields:

FieldHoldsConfidence
1Object ID, a varint. Unique across the whole document.Confirmed that it's unique (0001, 0002); that it identifies an object is likely, since other records refer to these numbers (0002).
2One message per payload (repeated)Confirmed
2.1A varint that differs between records with differently shaped payloads. Probably the payload's type.Unknown
2.2Three packed varints, such as 1 0 5. Probably a version.Unknown
2.3The payload's length in bytesConfirmed
2.5Packed varints: IDs of objects the payload refers toLikely (0022)
2.4Repeated; field 4 of each entry holds more referenced IDs as packed varints, and field 1 is probably the field path that holds themLikely (0022)
2.6Present in some headers; meaning not establishedUnknown

Most records have one payload. In a new document, six records in Document.iwa have two, with the same 2.1 value and different 2.2 values. Likely (0001)

Following references#

Every ID in header fields 2.5 and 2.4.4 is a reference in the record's payload. Confirmed (0022). They are the references that lead down the object tree. References back up, such as a style's or a text's link to the stylesheet, or a table drawable's link to its text, aren't listed. Likely (0022)

Every object in a document can be reached by starting at objects 1 (in Document.iwa), 2 (in Metadata.iwa) and 71 (in DocumentMetadata.iwa) and following the IDs in record headers, plus object 61 in ObjectContainer.iwa when a document has a chart. Confirmed: all 240,278 objects of the 353 samples, the 6 protected ones decrypted, were reached this way (0022, 0024, 0178, 0247, 0266). A document with a chart also has Index/ObjectContainer.iwa, whose object 61 (type 11008) is a fourth root, listing chart styles (0067).

Object 1, the document root, has a different type and layout in each app (type 10000 in Pages, type 1 in Keynote and in Numbers, and those two differ). Each embeds the same block of document properties as one large message (Pages field 15, Keynote field 3, Numbers field 8), holding the locale (field 1 starts with it, field 3 is the language) and the template path (field 9, such as Application/Blank/ISO). Likely (0027)

Password protection#

A document with a password has two extra files at the top of the package, .iwph and .iwpv2, and no previews. This holds in all three apps. Confirmed (0179, 0180)

  • .iwph holds the password hint as plain text.
  • .iwpv2 is 104 bytes: two 16-bit values (2 and 1, meaning unknown), a 32-bit iteration count (100,000), a 16-byte salt, a 16-byte IV, then 64 encrypted bytes. Decrypted, those are 32 random bytes followed by their SHA-256, which checks the password.

The key is PBKDF2-HMAC-SHA1 of the password (as UTF-8), using that salt and iteration count, 16 bytes long. Every .iwa part, every data file and BuildVersionHistory.plist is encrypted with it, using AES-128-CBC with PKCS #7 padding. DocumentIdentifier and Properties.plist are not encrypted. An encrypted part is laid out as 16 bytes of unknown meaning, the IV, the ciphertext, and 20 bytes of unknown meaning, probably an integrity check. Decrypted, a part is the same as in an unprotected document. The salt is new on every save. Confirmed (0179, 0180); that the password is UTF-8 is likely. iwork-probe --password decrypts documents this way; all six protected samples then frame and are fully reachable (0266).

View state#

ViewState.iwa holds how the document was last shown, which a reader can ignore. Its type-10133 record has the zoom as a scale factor in field 15 (1.25 for 125%), in field 33 whether two pages are shown side by side, and in field 28 whether change tracking is paused (0270). Likely (0241, 0242, 0270)

IDs and save-to-save changes#

Saving the same content twice can change these, and nothing else in the .iwa parts. Likely (0001, 0002)

  • The UUIDs in DocumentIdentifier, Properties.plist and Metadata.iwa record 2.
  • A creation time stored as text in the Document.iwa record of type 10012, and a time in CalculationEngine record type 4000.
  • 128-bit-looking values in CalculationEngine records.
  • The IDs of objects made at save time, and every reference to them. They changed between the two documents in 0001 but not between the two in 0002. Objects that come from the template keep their IDs.
  • The order of entries in one list in Metadata.iwa record 2.

When a document is saved again, existing objects keep their IDs and newly made ones (such as the view state) get new ones. Saving under a new name gives a new document UUID. Likely (0139, 0140)
