2. Text#

Where a Pages document keeps its body text, and how the text is encoded. Every finding links to the experiments that support it, with a confidence level as defined in CONTRIBUTING.md. Records, object IDs and types are as described in 1. Container.

Observed with Pages 15.4 on macOS 26.5.2. Keynote 15.4 stores slide text in type-2001 records laid out the same way, referring to the same kinds of styles (types 401, 2022, 2023), so this layer applies to Keynote text too. Likely (0025)

Field 3 of a type-2001 record is its text in all three apps. Writing a new string into field 3 is enough to change a single-paragraph text; Pages opens such a file and keeps the record as written (0288). With more paragraphs, a writer must add a paragraph-run entry (field 5) at each paragraph's start, or Pages rebuilds the table with the default paragraph style (0289). Confirmed over every sample of experiments 0001–0031 (0032). Field 1 seems to say what kind of text the record holds: in Pages 0 is the body, 1 a header or footer, 2 a footnote (0041) and 7 a table of contents (0202), Numbers uses 1 for text owned by a sheet, Keynote's presenter notes use 4 (0039), and Keynote's shape text leaves it out. Text can contain U+00AD (soft hyphen). Likely (0032)

The body text#

The body text is in Index/Document.iwa, in field 3 of a record of type 2001. Confirmed (0002, 0003)

  • It is UTF-8, including characters outside the Basic Multilingual Plane, which take four bytes.
  • It has no terminator or extra length prefix: the field's own length is the text's length in bytes.
  • An empty body has no field 3 at all.

Document.iwa holds more than one type-2001 record: 19 in a new document. The body's record has field 1 set to 0, and the other 18 have field 1 set to 1. Likely (0003). The other 18 hold header and footer text, and use the paragraph style named for headers and footers. Likely (0004, 0016). Field 1 says what a text storage is for: 0 a body, 1 a header or footer, 2 a footnote, 4 a slide's presenter notes and 7 a table of contents; text inside shapes, text boxes, placeholders and cells leaves it out. Likely, from a survey of every sample (0305)

Headers and footers#

Header and footer text is in type-2001 records, like the body. They are reached through the body's section runs (field 17), which point at a section (type 10011). Fields 23, 24 and 25 of a section each name a set of headers and footers (type 10143). In a set, field 1 lists the header and field 2 the footer, each as three text records in the order left, centre, right. A plain document uses the set in field 25. When section field 19 is 1, left-hand pages use the set in field 24 instead. Likely (0016, 0018, 0019). What the set in field 23 is for is unknown.

Other section fields hold switches from the Section tab of Pages' Document sidebar. Likely (0017)

Objects in the text#

An object placed in the text, such as a table, is the character U+FFFC (OBJECT REPLACEMENT CHARACTER) in the text, with an entry in the attachment runs (field 9) at that position. Likely (0020)

For a table, the attachment (type 2003, in Document.iwa) points at a drawable (type 6000, in CalculationEngine). The drawable holds the position and size in points (fields 1.1.1 and 1.1.2) and points at the table model (type 6001), whose fields 6, 7 and 8 are the number of rows, the number of columns and the table's name, and fields 9, 10 and 11 the numbers of header rows, header columns and footer rows (absent means 0; footer rows count within the rows, 0184), field 12 whether header rows are frozen (0125; fields 9 to 12 confirmed by writing them, 0301) and field 13 whether header columns are (0183); field 29 is 1 when header rows repeat on each page (0246). Rows, columns and name are confirmed (0120, 0122, 0123). A Numbers table's stored y is 28 points less than the y Numbers reports (0126). Sorting rewrites the rows (0119), and so does transposing, which also swaps fields 6 and 7 (0182). Likely (0020, 0060). A table's size is the sum of its row heights and column widths. The drawable's size can be out of date (0059).

The table model's field 4 holds its storage: 4.3 lists the tiles, each entry giving a tile index (4.3.1.1) and the tile record (4.3.1.2), and 4.1 and 4.2 name the row and column header storage buckets (type 6006). A bucket lists rows or columns with their own size in its repeated field 2: field 1 is the index, from 0, and field 2 the height or width in points as a float; unlisted rows and columns have the default size (0045; confirmed by writing them, 0308). Each tile covers 256 rows (field 4.3.2), and row numbers inside a tile are local, so a cell's row in the table is the tile index × 256 plus its row in the tile. A tile's field 4 counts its rows with content. Likely (0029, 0030), in Pages and Numbers alike. The row rule is confirmed (0030, 0063). Tiles without content are left out of the list, so a reader must use each entry's tile index. Likely (0063)

A table's cells are stored by row in its tile (type 6002, Index/Tables/Tile.iwa). Each row with content is one field-5 entry: 5.1 is the row index, 5.4 a table of 255 little-endian 16-bit offsets into the row's cell bytes (one per column, ffff for an empty cell), and 5.6 the cell bytes. A cell starts with a version byte (5) and a type byte: 2 for a number, stored as a little-endian IEEE 754 decimal128, and 3 for text, stored as a 32-bit key into a string table (type 6005, Index/Tables/DataList.iwa) whose entries hold the key in field 3.1, the number of cells using it in 3.2 and the string, as UTF-8, in 3.3 (0113, 0118). Equal texts share an entry, so changing an entry's string changes every cell using it (confirmed by writing it, 0306), and unused entries are removed (0114), and long texts are stored whole (0130). Confirmed (0021, 0026); all three apps store the same cells byte for byte, and keep formulas, merges and header counts the same way (0131–0137).

When a row has several cells, it is field 5.7, not 5.4, that holds their byte offsets. Likely (0031)

A cell's bytes 8–11 are little-endian flags saying which values and keys follow, in order of their bits. Further type bytes are 0 (no value, formatting only, 0138), 5 (date), 6 (boolean), 8 (a formula whose result is an error, stored with no value, 0078) and 10 (currency). Likely (0031)

The format list's entries give the kind of format in field 1, which decides how the cells using it are shown (confirmed by writing 258 over 256, 0307) (256 number, 257 currency, 258 percent, 259 scientific, 260 text, 261 date, 262 fraction, 263 checkbox, 267 rating, 268 duration, 269 numeral system (0181), whose field 8 is probably the base), plus its details, such as a currency code or a date pattern. A formula cell also keeps its last result as a value, as a cell of the result's type: a date, or text through the string table (0108, 0110). Writing a new decimal128 in place of a cell's value changes the cell, so nothing else caches it (0290). A negative decimal128 has its sign bit set, confirmed (0112, 0174). Text that looks like a number is stored as a number unless the cell's format is text (0176). Likely (0031)

An image placed on the page, rather than in the text, is a record of type 3005 in Document.iwa, listed next to the body text by page-level records (types 10015 and 10010). It holds its position and size in points in field 1.1, like a table's drawable, and the data ID of its file in field 11.1, with a reduced copy for a large image in field 12 (0148) (see container.md). Likely (0023). Field 9 is its natural size and fields 1.1.2 and 4 the size it is drawn at (0055). Field 3 names its image style (type 3016), whose field 11.2 is the opacity from 0 to 1 (0057) and 11.4 the reflection, with its strength in 11.4.1 (0099; both confirmed by writing them, 0304). Image field 7 is 1 for a media placeholder, an image the user is meant to replace (0244). Image field 14 holds adjustments as fractions (exposure in 14.1, saturation in 14.2), and field 15 names a pre-rendered …-filtered-N copy to draw (0284). Remove Background leaves the image file alone: field 10 holds the subject's outline as a path in the image's pixels, field 22 is 1, and a mask crops to the subject (0285). Image field 5 names a mask (type 3006): a drawable placed relative to the image, whose outline, in the path form of shapes, clips it; the image file itself isn't cropped (0245).

A text box, a shape and a line are all shapes of type 2011, listed by the same page-level record. A shape's position and size are in field 1.1, its outline path in 1.3 (either a path in 1.3.5, with a natural size in 5.2 and elements in 5.3.1 whose kind is 1 move, 2 line, 4 cubic curve (two control points, then the end point, 0218) or 5 close; or, once made editable, a list of nodes with control points in 1.3.8, 0217; or a parametric shape in 1.3.4: kind 0 a rounded rectangle with its radius, kind 1 a polygon with its number of sides, 0219; or one in 1.3.3 with a pair of numbers: kind 100 a star with its points and inner ratio, kind 1 an arrow with its head position and shaft thickness, 0220; or a callout in 1.3.6, with its box size in field 1 and corner radius in field 3, 0221) and its style (type 2025, such as textbox-0-shapestyle, shape-0-shapestyle or line-0-shapestyle) in 1.2. Fields 2 and 4 name its text, a type-2001 record with no field 1. Likely (0049, 0050, 0051) A shape style keeps its properties one level deeper than text styles, in field 1.11; field 1.11.1.1 is the fill colour, in the same colour layout as text colour, and 1.11.3 the opacity. Likely (0077, 0098) The fill can hold a gradient in 1.11.1.2 instead of a colour: its kind in field 1 (0 linear, 1 radial, 0275), whether the advanced editor made it in field 4 (0283), stops in its field 2 (each a colour, a position from 0 to 1 and a midpoint) and the angle in radians in 5.2 (0260). Field 1.11.2 is the stroke: its colour in 2.1, its width in points in 2.2, and its pattern kind in 2.6.1, 1 for a solid line and 2 for none, as in the default style (0250), or 0 for a dash pattern whose lengths are in 2.6.4, the count used in 2.6.3 (0274). Field 1.11.4 is the shadow: colour (1), angle in degrees in page coordinates, with y down (2, 90 for a shadow below; the sidebar shows 360° minus it, 0278), offset in points (3), blur (4), opacity (5) and whether it is shown (6) (0251). The presets in the sidebar are named styles shape-N-shapestyle that shapes point at directly, confirmed (0215).

A group is a type-3008 drawable listing its members in field 2. Its geometry is the box around them; each member names the group in its field 1.2 and is positioned relative to the group's corner. Only the group is listed on the page. Likely (0216)

An object is either in the text (a U+FFFC with an attachment, and its drawable's field 1.2 names that text) or on the page (listed by type 10015, with no field 1.2). Likely (0020, 0052)

In the geometry of any drawable (field 1.1), 1.1.1 is the position and 1.1.2 the size of the unrotated box, in points, and 1.1.4 its rotation in degrees about its centre, counter-clockwise on the page (confirmed, 0056, 0097). Field 1.1.3 holds flags, normally 3; bit 0x4 is a horizontal flip (0213). A vertical flip is stored as a horizontal flip plus a rotation of 180° (0214). Fields 1.10 and 1.11 name the object's title and caption: type-633 text shapes, with field 3 = 2 for a title and 1 for a caption, or type-3097 placeholders when hidden, confirmed (0228, 0229). Numbers tables get captions the same way (0231). Field 1.5 is 1 for a locked object (0100; position, size, rotation and lock confirmed by writing them, 0303, where AppleScript's position turned out to be the corner of the rotated object's bounding box) and field 1.8 is its accessibility description, in Keynote and Pages alike (confirmed, 0102, 0177). A line is a box of zero height, rotated. Likely (0051)

Paragraphs#

A paragraph break is a character in the text. Pressing Return in Pages writes U+000A (line feed). A U+000D (carriage return) set through AppleScript is kept as given and also starts a paragraph. The last paragraph has no break after it. Confirmed for U+000A (0005, 0006); likely for U+000D (0005).

Pressing Shift-Return writes U+2028 (line separator), a line break that doesn't start a paragraph. Likely (0006)

A page break (Insert → Page Break) is the character U+0005, and it also starts a new paragraph. Likely (0018) A column break (Insert → Column Break) is U+000C, and also starts a new paragraph. Likely (0210)

A tab (U+0009) and a non-breaking space (U+00A0) are plain characters with no runs of their own. Likely (0058)

A section break (Insert → Section Break) is the character U+0004. It starts a new paragraph and a new section: the section runs (field 17) gain an entry at the next character, pointing at a new section record with its own header-and-footer sets. Likely (0040)

Positions in the text#

Positions in the text count UTF-16 code units, not UTF-8 bytes or code points. So a character outside the Basic Multilingual Plane counts as 2, and an emoji joined from several (such as 👨‍👩‍👧) counts every unit, joiners included. A reader has to convert positions before using them on the UTF-8 text. Confirmed (0003, 0004, 0149)

No writing direction is stored for right-to-left text set through AppleScript; lay text out by the Unicode bidirectional rules. Likely (0150)

Runs#

Several fields of a type-2001 record are run tables: lists of entries that apply something to ranges of the text. Each entry is a message whose field 1 is the position where a run starts. Where the run applies an object, its field 2 is a message whose field 1 is that object's ID. A run lasts until the next entry, or to the end of the text. Confirmed (0004, 0005, 0008). Ranges with the same formatting point at the same object. Confirmed (0008, 0054) What an entry with no field 2 means depends on the table: in field 8 it ends a character style, in field 5 it doesn't.

Styles#

Changing the size of part of the text, or making it bold or italic, creates a new, unnamed character style (type 2021) in DocumentStylesheet.iwa. It inherits (field 1.3) from a character style whose identifier is character-style-null. Confirmed (0004, 0007, 0008)

Formatting a whole paragraph instead creates an unnamed paragraph style (type 2022) that inherits from the paragraph's style and carries the change. Likely (0008, 0149)

Several properties set on one range go into one style (0152). Setting a property to the value it already has makes no style (0153), and styles nothing uses are dropped on save (0154). A template's styles are copied into the document with their own values, such as white text in the black template (0157). Likely

Field 11 of a character style or a paragraph style holds the character properties it sets. A property that is left out is inherited, and one set to 0 is turned off. Likely (0004, 0007, 0008)

Named styles such as Body set every property; unnamed ones set only what differs from their parent (field 1.3). Likely (0010)

Field 10 has equalled the number of properties set in every unnamed style so far, and is 57 in the named paragraph styles, which set 59. It doesn't count edits. Unknown (0010, 0011, 0152)

A list style (type 2023) stores most properties as nine repeated values, one per list level. Field 11 is the kind of marker (0 none, 2 a text character, 3 a number), field 16 the marker text for kind 2, and field 13 an indent in points that grows by a fixed step per level. Likely (0014)

To find a character's formatting, take each property from the first style that sets it. Look first in its character style (from the field-8 runs), then that style's parent (field 1.3), and so on. Then look in its paragraph style (from the field-5 runs) and that style's parents. A property set to 0 counts as set. A font name in 11.5 may already include a weight, such as HelveticaNeue-Bold. Likely for bold, italic, size and font: the rule predicted Pages' own reading of all 19 words of 8 documents (0033, 0034). It also holds for text colour (0042).

Styles get their own layer once more of them are understood.
