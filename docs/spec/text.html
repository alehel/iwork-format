2. Text#

Where a Pages document keeps its body text, and how the text is encoded. Every finding links to the experiments that support it, with a confidence level as defined in CONTRIBUTING.md. Records, object IDs and types are as described in 1. Container.

Observed with Pages 15.4 on macOS 26.5.2. Keynote 15.4 stores slide text in type-2001 records laid out the same way, referring to the same kinds of styles (types 401, 2022, 2023), so this layer applies to Keynote text too. Likely (0025)

Field 3 of a type-2001 record is its text in all three apps. Writing a new string into field 3 is enough to change a single-paragraph text; Pages opens such a file and keeps the record as written (0288). With more paragraphs, a writer must add a paragraph-run entry (field 5) at each paragraph's start, or Pages rebuilds the table with the default paragraph style (0289). Confirmed over every sample of experiments 0001–0031 (0032). Field 1 seems to say what kind of text the record holds: in Pages 0 is the body, 1 a header or footer, 2 a footnote (0041) and 7 a table of contents (0202), Numbers uses 1 for text owned by a sheet, Keynote's presenter notes use 4 (0039), and Keynote's shape text leaves it out. Text can contain U+00AD (soft hyphen). Likely (0032). Pages breaks a word there when it reaches the end of a line, drawing a hyphen, even with hyphenation off, and draws nothing elsewhere (confirmed by writing it, 0436).

The body text#

The body text is in Index/Document.iwa, in field 3 of a record of type 2001. Confirmed (0002, 0003)

  • It is UTF-8, including characters outside the Basic Multilingual Plane, which take four bytes.
  • It has no terminator or extra length prefix: the field's own length is the text's length in bytes.
  • An empty body has no field 3 at all.

Document.iwa holds more than one type-2001 record: 19 in a new document. The body's record has field 1 set to 0, and the other 18 have field 1 set to 1. Likely (0003). The other 18 hold header and footer text, and use the paragraph style named for headers and footers. Likely (0004, 0016). Field 1 says what a text storage is for: 0 a body, 1 a header or footer, 2 a footnote, 4 a slide's presenter notes and 7 a table of contents; text inside shapes, text boxes, placeholders and cells leaves it out. Likely, from a survey of every sample (0305). Pages relies on it: a body storage with another kind, or a header storage marked as a body, makes Pages quit while opening the document (confirmed by writing them, 0451)

Objects in the text#

An object placed in the text, such as a table, is the character U+FFFC (OBJECT REPLACEMENT CHARACTER) in the text, with an entry in the attachment runs (field 9) at that position. Confirmed by writing them: moving both moves the object, and moving either alone leaves it undrawn (0020, 0423)

Tables are described in 4. Tables, and images, shapes, groups and charts in 5. Drawables, media and charts.

Paragraphs#

A paragraph break is a character in the text. Pressing Return in Pages writes U+000A (line feed). A U+000D (carriage return) set through AppleScript is kept as given and also starts a paragraph. The last paragraph has no break after it. Confirmed for U+000A (0005, 0006); likely for U+000D (0005).

Pressing Shift-Return writes U+2028 (line separator), a line break that doesn't start a paragraph. Likely (0006); confirmed by writing one (0360)

A page break (Insert → Page Break) is the character U+0005, and it also starts a new paragraph (confirmed by writing one, 0359). Likely (0018) A column break (Insert → Column Break) is U+000C, and also starts a new paragraph (confirmed by writing one, 0360). Likely (0210)

A tab (U+0009) and a non-breaking space (U+00A0) are plain characters with no runs of their own. Likely (0058); confirmed by writing them (0369): a tab moves to the next stop and a non-breaking space keeps its words on one line.

A section break (Insert → Section Break) is the character U+0004. It starts a new paragraph and a new section: the section runs (field 17) gain an entry at the next character, pointing at a new section record with its own header-and-footer sets. Confirmed by writing (0040, 0361): the character alone makes the break; if the section runs don't follow, Pages makes the missing section and writes it on saving. Two runs may point at the same section record.

Positions in the text#

Positions in the text count UTF-16 code units, not UTF-8 bytes or code points. So a character outside the Basic Multilingual Plane counts as 2, and an emoji joined from several (such as 👨‍👩‍👧) counts every unit, joiners included. A reader has to convert positions before using them on the UTF-8 text. Confirmed (0003, 0004, 0149)

No writing direction is stored for right-to-left text set through AppleScript; lay text out by the Unicode bidirectional rules. Likely (0150). A paragraph's base direction doesn't come from its first strong character: in a left-aligned Body paragraph, Pages 15.4 starts an Arabic line at the left margin and lays the runs out from the left (confirmed by writing them, 0441). That was tested with one style only. How a paragraph set to right-to-left in the app stores its direction, and whether another style can carry it, is unknown. A reader using a left-to-right base direction matches Pages for text like this, but may not for a paragraph set to right-to-left in the app.

Runs#

Several fields of a type-2001 record are run tables: lists of entries that apply something to ranges of the text. Each entry is a message whose field 1 is the position where a run starts. Where the run applies an object, its field 2 is a message whose field 1 is that object's ID. A run lasts until the next entry, or to the end of the text. Confirmed (0004, 0005, 0008). Ranges with the same formatting point at the same object. Confirmed (0008, 0054) What an entry with no field 2 means depends on the table: in field 8 it ends a character style, in field 5 it doesn't.
