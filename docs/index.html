The iWork file formats#

This site specifies the files that Apple's Pages, Keynote and Numbers save: .pages, .key and .numbers. Apple doesn't publish the formats. Everything here was found from the outside, by changing one thing in a document, saving it, and recording what changed in the file. No Apple code was read, disassembled or decompiled.

Each finding links to the experiments that support it and carries a confidence level:

LevelMeaning
ConfirmedAt least two experiments agree
LikelyOne experiment supports it, and nothing contradicts it
UnknownSeen in files, but its meaning isn't established yet

The findings come from Pages, Keynote and Numbers 15.4 on macOS 26.5.

Where to start#

  • Reading a Pages document takes one small file, a page with the word hello, from its ZIP listing down to the bytes that hold the word. Read it first: every other page assumes it.
  • Reading a Numbers table follows a spreadsheet's root to its cells and decodes a row byte by byte.
  • Writing a document shows that the spec is complete enough to write files the apps accept.
  • Sample files lists the documents used on these pages, for download.

In brief#

A document is a ZIP file, stored without compression. Most of it is in .iwa parts under Index/. Each part is a series of chunks of Snappy-compressed data. Once decompressed, a part is a list of records: each is a Protocol Buffers header, giving the object's ID, type and length, followed by the object itself as a Protocol Buffers message. Objects refer to each other by ID, and every object can be reached from the root objects.

document.pages (ZIP)
├── Index/Document.iwa ──► chunks ──► Snappy ──► records ──► objects
├── Index/DocumentStylesheet.iwa
├── …
├── Metadata/Properties.plist
└── preview.jpg

There is no schema in the file. Field numbers, types and their meanings are what this specification provides.

Tools#

The repository holds iwork-probe, a command-line tool written from this specification, which lists parts, decodes chunks and records, prints messages and follows references. The excerpts on these pages are its output. A small Python writer, using only the standard library, writes documents back (0287).
